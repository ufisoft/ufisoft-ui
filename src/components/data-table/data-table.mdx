# DataTable

A data table for admin screens: sortable columns and pages, on the client or the server.

<Canvas of={DataTableStories.Default} />

## When to use

- Lists of records users scan, sort and page through: users, orders, pages, logs.
- Data that lives on a server and is fetched page by page (`mode="server"`).

## When not to use

- A small, fixed table with no sorting or paging (a pricing comparison, a spec sheet) — use `Table`.
- A list of cards or media — use `Grid`.
- Key–value details of one record — use a description list or `Stack`.

## Props

<ArgTypes of={DataTableStories} />

**Columns.** Each column has an `id`, a `header` and usually a `value` — what it sorts by and what it shows. `cell` renders custom content (a `Badge`, a link, actions); `compare` gives the column its own order. A column with `value` or `compare` is sortable unless `sortable={false}`. Without `cell`, numbers and dates are formatted for `locale`.

**Rows.** `data` is the rows; `getRowId` gives each a stable id (it defaults to the index — set it when rows can be sorted or removed).

**Client or server.** `mode="client"` (default) sorts and pages `data` itself. `mode="server"` shows `data` as the current page and `totalCount` as the total; every change is reported so your server does the work:

```tsx
const [query, setQuery] = useState<DataTableQuery>({ sort: [], page: 1, pageSize: 25 });
const { rows, total, isLoading } = useUsers(query); // your fetch

<DataTable
  caption="Users"
  mode="server"
  columns={columns}
  data={rows}
  totalCount={total}
  loading={isLoading}
  sort={query.sort}
  page={query.page}
  pageSize={query.pageSize}
  onQueryChange={setQuery}
/>;
```

`onQueryChange` receives `{ sort, page, pageSize }` after every change — one place to fetch from. The separate `onSortChange`, `onPageChange` and `onPageSizeChange` also fire.

**State.** Sort, page and page size each work controlled (`sort` + `onSortChange`) or uncontrolled (`defaultSort`). A new sort or page size goes back to page 1. Keep the query in the URL or a store (`createStore`) to restore a view.

**Labels.** `labels` translates every text, including the range (“1–10 of 245”) and the sort description; `locale` sets text sorting and number formatting.

## Accessibility

- It is a native `<table>` with a caption; the table scrolls inside a focusable region named by the caption.
- Sortable headers are buttons: Enter or Space sorts, Shift+click adds a secondary sort. The primary sorted column has `aria-sort`; every sorted header's button is described as “sorted ascending/descending” (with its priority when several columns sort).
- The range (“11–20 of 245”) and “Loading…” are in a status region, so page changes and loading are announced politely. Errors are announced with `role="alert"`.
- The rows-per-page select and the pagination are labelled; translate them with `labels`.
- Shift+click has no keyboard equivalent beyond Shift+Enter in most browsers — offer a preset view (as in the controlled example) when a multi-column order matters.

## Do / Don't

| Do                                                           | Don't                                                    |
| ------------------------------------------------------------ | -------------------------------------------------------- |
| Set `getRowId` to the record id.                             | Rely on the index when rows sort, page or get removed.   |
| Use `mode="server"` for large or remote data.                | Load 10,000 rows into the browser to sort them.          |
| Give actions columns a visible label and real buttons/links. | Make the whole row clickable as the only way to open it. |
| Keep the query in the URL for shareable views.               | Reset the user's sort on every data refresh.             |
