# Textarea

A multi-line text field. A styled native `<textarea>` that works controlled or uncontrolled and with any form library.

<Canvas of={TextareaStories.Default} />

## When to use

- Free text that may span several lines: comments, notes, descriptions, addresses.

## When not to use

- Short single-line values (name, email, search) — use `Input`.
- Rich text with formatting — use a dedicated editor.

## Props

<ArgTypes of={TextareaStories} />

All native `<textarea>` attributes are supported. `rows` defaults to `3`; the user can resize the field vertically.

Inside a `FormField`, `id`, `aria-describedby`, `aria-invalid`, `required` and `disabled` come from the field.

## Sizes

<Canvas of={TextareaStories.Sizes} />

Sizes match `Input` padding and font size, and a size is never shorter than the matching `Input`, so the two line up in one form.

## Accessibility

- Every textarea needs a label: a `FormField` + `FormLabel`, or `aria-label` when no visible label exists.
- `Enter` inserts a new line; it never submits the form.
- `invalid` sets `aria-invalid`; pair it with a `FormMessage` explaining the problem.
- With `maxLength`, state the limit in a `FormDescription` — the native limit silently stops typing.

## Do / Don't

| Do                                         | Don't                                           |
| ------------------------------------------ | ----------------------------------------------- |
| Use a visible label.                       | Use `placeholder` as the label.                 |
| Set `rows` to the length you expect.       | Use a one-row textarea instead of an `Input`.   |
| Describe a `maxLength` limit in the field. | Cut text off without telling the user.          |
| Use `readOnly` for non-editable text.      | Use `disabled` for text the user needs to read. |

## Related components

- `Input` — single-line text.
- `FormField` — label, description and validation wiring.
